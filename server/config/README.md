# Конфигурация радиоканалов

Файл `server/config/radio-channels.json` описывает радиоканалы и группы доступа к ним. Сервер читает его при запуске, поэтому после изменения файла контейнер нужно пересобрать или перезапустить с актуальной копией.

## 1. Формат файла

```json
{
  "channels": [
    {
      "id": "police",
      "name": "Полиция",
      "description": "Канал сотрудников полиции",
      "priority": 1,
      "access": [
        {
          "label": "Основной Discord",
          "guildId": "123456789012345678",
          "roleIds": ["234567890123456789"]
        },
        {
          "label": "Второй Discord",
          "guildId": "345678901234567890",
          "roleIds": ["456789012345678901", "567890123456789012"]
        }
      ]
    }
  ]
}
```

Поля канала:

| Поле | Обязательно | Назначение |
|---|---|---|
| `id` | да | Уникальный идентификатор: `[a-z0-9_-]`, до 64 символов |
| `name` | да | Название для клиента, до 64 символов |
| `description` | нет | Описание для клиента, до 200 символов |
| `priority` | нет | Порядок сортировки, по умолчанию `0` |
| `access` | нет | Массив групп доступа. Пустой массив — открытый канал |

Поля группы доступа:

| Поле | Обязательно | Назначение |
|---|---|---|
| `guildId` | да | ID Discord-сервера, на котором проверяется роль |
| `roleIds` | да | Непустой массив ID ролей этого сервера |
| `label` | нет | Понятная подпись группы для администратора, до 64 символов |

Доступ разрешён, если пользователь имеет **хотя бы одну** роль **хотя бы в одной** группе. Если `access` отсутствует или равен `[]`, канал открыт любому авторизованному пользователю.

`label` ни на что не влияет и не отправляется клиенту. Он нужен только для удобства чтения конфигурации.

## 2. Несколько Discord-серверов

В `.env` задайте основной сервер и дополнительные:

```dotenv
DISCORD_GUILD_ID=123456789012345678
DISCORD_ROLE_GUILD_IDS=345678901234567890,456789012345678901
```

- `DISCORD_GUILD_ID` — основной сервер проекта. Он нужен для Bloxlink и всегда включается в проверку ролей.
- `DISCORD_ROLE_GUILD_IDS` — дополнительные серверы через запятую, не более 20. Их роли тоже могут выдавать радиоканалы.
- Бот из `DISCORD_BOT_TOKEN` должен состоять на **каждом** сервере из этого списка и иметь право просматривать участников.
- `guildId` в `access` должен входить в основной или дополнительный список. Иначе сервер отключит радио и напишет ошибку в лог.

Если `DISCORD_BOT_TOKEN` не задан, открытые каналы продолжат работать, а закрытые будут недоступны.

## 3. Пример: один канал на два сервера

```json
{
  "channels": [
    {
      "id": "police",
      "name": "Полиция",
      "description": "Общий канал полиции двух Discord-серверов",
      "priority": 1,
      "access": [
        {
          "label": "Полиция — основной сервер",
          "guildId": "123456789012345678",
          "roleIds": ["234567890123456789"]
        },
        {
          "label": "Полиция — второй сервер",
          "guildId": "345678901234567890",
          "roleIds": ["456789012345678901"]
        }
      ]
    }
  ]
}
```

Пользователь с ролью `234567890123456789` на основном сервере или с ролью `456789012345678901` на втором получит доступ к каналу `police`.

## 4. Пример: разные каналы для разных групп

```json
{
  "channels": [
    {
      "id": "dispatch",
      "name": "Диспетчерская",
      "description": "Диспетчеры и руководство",
      "priority": 1,
      "access": [
        {
          "label": "Диспетчеры",
          "guildId": "123456789012345678",
          "roleIds": ["234567890123456789"]
        },
        {
          "label": "Руководство",
          "guildId": "123456789012345678",
          "roleIds": ["345678901234567890"]
        }
      ]
    },
    {
      "id": "public",
      "name": "Общий канал",
      "description": "Доступен всем авторизованным пользователям",
      "priority": 2,
      "access": []
    }
  ]
}
```

## 5. Где взять ID

1. В Discord включите **Настройки → Расширенные → Режим разработчика**.
2. Правый клик по серверу → **Копировать ID сервера** — это `guildId`.
3. Правый клик по роли → **Копировать ID роли** — это элемент `roleIds`.

ID ролей и серверов не являются секретами, но не публикуйте их без необходимости.

## 6. Устаревший формат

Раньше использовалось поле `roleIds` без `guildId`:

```json
{
  "id": "police",
  "name": "Полиция",
  "roleIds": ["234567890123456789"]
}
```

Такой формат всё ещё поддерживается: роль проверяется на всех настроенных Discord-серверах. Для новых каналов используйте `access` — он явно показывает, на каком сервере выдаётся роль. Нельзя одновременно указывать `access` и `roleIds` в одном канале.

## 7. Применение изменений

При запуске в Docker файл копируется в образ. После редактирования:

```bash
cd server
docker compose build server
docker compose up -d server
```

Если файл смонтирован в контейнер как volume, достаточно перезапустить сервис:

```bash
docker compose restart server
```

Проверьте логи:

```bash
docker compose logs --tail=100 server
```

При ошибке конфигурации радио отключается, а причина пишется в лог. Сервер при этом продолжает работать.
